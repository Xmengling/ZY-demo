🌿 中医经方 AI 智能问诊系统

基于 LLM + Agent + RAG 的经方方证辨证智能助手
让千年经方智慧，触手可及

一、创意介绍

中医经方 AI 智能问诊系统 是一个面向中医学习者和临床医师的智能辅助平台，深度融合 大语言模型（LLM）+ Agent 智能体 + RAG 检索增强生成 三大技术，以《伤寒论》《金匮要略》经方体系为核心，提供 AI 智能问诊、方证辨证、知识库检索、经方学习 等一站式服务。

想解决什么问题：中医经方辨证体系庞大复杂，学习者难以快速掌握方证对应关系；基层医师缺少高效的辨证辅助工具。我们希望用 AI 降低经方学习的门槛，辅助临床辨证决策。
为什么想到做这个：团队长期从事中医经方学习研究，深感"方证辨证"虽高效但入门门槛高。胡希恕、李冠杰等经方大家的学术思想散落各处，需要一个系统化的 AI 工具来整合、检索和辅助应用。

产品形态：Web 应用（PC + 移动端自适应），支持独立部署和云端访问。

二、目标用户及痛点

核心用户群体

  • 中医学生与自学者：面对数百首经方和海量条文，难以快速建立方证对应的辨证思维
  • 基层中医师：临床中遇到复杂病症，需要快速检索相关方证、参考经方名家医案
  • 中医爱好者：对经方感兴趣但缺乏系统学习路径，需要 AI 引导式问诊学习

使用场景

  • 临床辅助：医师输入患者症状，AI 通过多轮对话收集四诊信息，给出可能的方证方向
  • 学习研究：学生通过智能问诊模拟临床辨证，结合知识库深入理解方证病机
  • 方剂查阅：快速检索 100+ 经方的组成、条文、病理、辨证要点、名家解读和医案
  • 条文学习：系统化学习《伤寒论》原文，AI 辅助解读和方证对应

当前痛点

没有我们的产品，用户现在面临：📚 方证资料分散各处难以检索；🩺 辨证缺乏 AI 辅助，依赖个人经验；⏳ 学习效率低，难以快速建立方证思维；🔍 无法将条文、方剂、医案、名家解读有机串联。

三、核心功能

🤖

AI 智能问诊

多轮对话收集症状/舌脉，Agent 以「方证辨证」思路结合知识库分析，WebSocket 流式输出辨证建议

📚

经方知识库

基于 FAISS 向量数据库的 380+ 中医经方方证知识精准检索，覆盖 100+ 经方的完整方证分析

💊

方剂解读卡片

每首方剂包含组成、条文、病理、辨证要点、名家解读、医案对比，支持 PNG 导出分享

📖

伤寒论学习

系统化条文学习模块，支持逐条解读、方证对应、关键词搜索，AI 辅助理解经典

💾

问诊记录管理

持久化存储问诊会话与消息，支持历史回溯、分类查看

🔐

用户认证体系

注册 / 登录 / JWT 鉴权，保障用户数据安全与隐私

四、技术架构

Vue3 前端 → FastAPI 后端 → LLM Agent → FAISS 向量库
Vue 3 + Element Plus FastAPI + SQLAlchemy DeepSeek LLM FAISS 向量检索 RAG 检索增强 WebSocket 流式输出 SQLite / PostgreSQL JWT 鉴权 Docker 部署

系统采用前后端分离架构，前端 Vue3 通过 HTTP REST + WebSocket 与后端 FastAPI 通信。后端 Agent 层负责症状分析 + RAG 编排 + 方证辨证，LLM 层接入 DeepSeek 大模型，RAG 层基于 FAISS 向量数据库实现中医经方方证知识的高效检索。支持离线规则模式兜底，无 LLM 也能给出基于知识库的辨证建议。

五、价值与意义

📚 社会价值

降低中医经方学习门槛，让更多人受益于传统医学智慧。辅助基层医疗，缓解优质中医资源分布不均的问题。

⚡ 效率提升

将方证检索从"翻书半小时"缩短到"对话 30 秒"。AI 辅助辨证，让学习者快速建立方证思维，加速临床经验积累。

核心竞争力：不同于通用 AI 问诊，我们聚焦「经方方证辨证」这一细分领域，将胡希恕、李冠杰等经方大家的学术体系深度结构化，构建了 380+ 条高质量的方证知识库，让 AI 真正做到"有据可依、有方可查"。
