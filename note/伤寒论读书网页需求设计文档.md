# 《伤寒论》读书 Skill 网页化需求设计文档

## 1. 项目定位

把项目中已有的《伤寒论逐条上课读书 Skill》做成一个可长期使用的网页学习工具。

这个网页不是普通文章阅读器，也不是单纯 AI 聊天窗口，而是一个“课堂式读书系统”：每天从当前进度开始，先抽查，再派任务，再按片段带读，最后小测和记录进度。

核心价值：

- 让用户每天稳定推进 1 条到 5 条《伤寒论》条文。
- 把“原文阅读、用户归纳、系统点评、小测复盘”固定成网页流程。
- 自动保存进度、错题、掌握度和下次复习重点。
- 保留胡希恕、李冠杰讲稿原文，不把学习变成纯 AI 总结。

## 2. 用户目标

用户打开网页后，希望立即知道三件事：

- 今天从哪一条开始学。
- 当前只需要回答哪一个问题。
- 学完以后系统会自动记住什么。

用户不需要先翻文档、找进度、复制 prompt，也不需要在聊天里反复提醒“按我的 skill 学”。

## 3. 产品原则

### 3.1 课堂节奏优先

页面默认进入课堂，不默认进入资料库。每次只展示当前条文、当前片段和当前问题。

### 3.2 原文先行

胡希恕、李冠杰部分必须先展示讲稿原文节选，再让用户归纳。用户没有归纳前，不展示系统总结。

### 3.3 一问一答

每个片段结束只问一个问题。用户回答后再进入点评或下一片段。

### 3.4 进度可恢复

用户中途停止后，下次打开网页应能从停止处继续，而不是重新从首页选择。

### 3.5 术语忠实

讲稿明确使用 `表虚证`、`表实证`、`里热`、`水气` 等术语时，网页展示和系统点评必须优先保留原术语。病理分类只作辅助，不强行替代原文术语。

## 4. MVP 范围

第一版先做“单人课堂学习闭环”，包含：

- 今日任务卡
- 当前条文学习
- 分片段阅读
- 用户归纳输入
- 系统点评
- 提示 / 答案 / 换个说法
- 本条小测
- 学习进度保存
- 错题和薄弱点记录

第一版暂不做：

- 多用户班级
- 排行榜
- 社区评论
- 大规模题库后台
- 方剂卡片编辑器重构
- PDF 导出

## 5. 信息架构

### 5.1 主导航

建议保留 4 个一级入口：

- `今日学习`
- `条文目录`
- `复习错题`
- `学习记录`

### 5.2 今日学习

这是默认首页，也是最重要页面。

页面结构：

- 顶部：当前进度、今日模式、当前关卡、积分
- 左侧：今日任务卡、课前抽查、已完成片段
- 中间：当前条文和当前片段
- 右侧：用户输入、提示按钮、小测结果、进度摘要

### 5.3 条文目录

用于查看整体进度，不作为主学习入口。

每条显示：

- 条文编号
- 掌握度：熟 / 半熟 / 生 / 卡住 / 未学
- 是否有错题
- 是否已收集症状卡、病理卡、边界卡
- 最近学习日期

### 5.4 复习错题

集中处理薄弱点。

支持按以下维度筛选：

- 原文记忆
- 病理分类
- 方证边界
- 误治判断
- 类方鉴别

### 5.5 学习记录

展示每日学习流水。

每条记录包含：

- 日期
- 今日已读条文
- 学习模式
- 上课状态
- 今日得分
- 小测等级
- 掌握度
- 今日最重要抓手
- 错题 / 薄弱点
- 下次从哪一条开始

## 6. 核心学习流程

### 6.1 进入页面

用户打开网页后，系统读取当前进度，展示：

- 下一次从：第 X 条
- 默认模式：轻量版 / 标准版 / 深入版
- 今日建议：继续新课 / 先复习错题 / 只做轻量版

如果存在 `卡住` 或错题，课前抽查优先从薄弱点开始。

### 6.2 课前点名

页面先让用户选择状态：

- 清醒
- 一般
- 很散

系统根据状态调整：

- 清醒：标准版或深入版，当天最多 5 条
- 一般：标准版，先完成 1 条
- 很散：轻量版，只完成 1 条原文抓手和 1 道题

### 6.3 课前抽查

新课前先问 1 道旧题。

题型优先级：

- 上次错题
- 掌握度为 `生` 或 `卡住` 的条文
- 上一条最重要抓手

抽查题不要求复杂，目标是把用户拉回经方语境。

### 6.4 今日任务卡

任务卡固定展示：

```markdown
## 今日任务卡

- 当前条文：第X条
- 今日主线：这一条主要辨什么
- 必须掌握：
  1. 核心症状组合
  2. 病理或方证边界
  3. 最容易误解的地方
- 下课前要会回答：
  - 用自己的话复述本条抓手
```

### 6.5 分片段带读

标准版默认片段顺序：

1. 原文片段
2. 胡希恕原文阅读
3. 用户归纳
4. 胡希恕点评
5. 李冠杰原文阅读
6. 用户归纳
7. 李冠杰点评
8. 病理分类和一句话记忆
9. 本条小测

每个片段必须有明确状态：

- 未开始
- 阅读中
- 等待用户回答
- 已点评
- 已完成

### 6.6 原文阅读片段

胡希恕、李冠杰原文阅读片段必须只展示原文和归纳问题。

示例结构：

```markdown
### 胡希恕原文阅读

讲稿原文节选：
> ...

请你先归纳：
- 这段主要讲了什么？
- 你觉得最重要的症状、病理或边界是哪一个？
```

用户提交归纳后，系统再展示点评：

```markdown
### 胡希恕点评

你抓得对的是：
- ...

需要补充的是：
- ...

我的总结：
- ...
```

### 6.7 小测与评级

每条结束至少 1 到 2 题。

题型包括：

- 原文填空
- 病理判断
- 方证边界
- 误治判断
- 小病例辨析

系统根据表现给出：

- 小测等级：A / B / C
- 掌握度：熟 / 半熟 / 生 / 卡住
- 下次复问建议

### 6.8 是否继续

每条结束后页面必须停住，询问：

```text
这一条过了吗？要不要进入下一条？
```

用户选择：

- 继续下一条
- 今天到这里
- 复习本条
- 标记为卡住

## 7. 页面交互设计

### 7.1 当前片段卡

当前片段是页面视觉中心。

需要展示：

- 条文编号
- 片段名称
- 讲稿来源
- 正文内容
- 当前问题
- 用户回答输入框
- 操作按钮

操作按钮：

- 提示
- 答案
- 换个说法
- 举例
- 跳过
- 停

### 7.2 输入区

输入区支持两类回答：

- 文本归纳
- 选择题 / 判断题作答

输入后系统进入对应状态：

- 原文归纳：进入点评
- 小测答案：进入判题
- 控制指令：执行提示、答案、解释、跳过或停止

### 7.3 提示机制

提示最多两级：

- 提示一：指出关键词
- 提示二：缩小判断范围
- 答案：公布答案并解释

页面要显示当前提示层级，避免用户重复点提示时直接刷出长答案。

### 7.4 状态降级

用户选择 `很散`，或连续两次答不出时，系统建议降级：

- 标准版降为轻量版
- 深入版降为标准版

降级后仍要保存今天已完成内容，不把当天标记为失败。

## 9. 接口设计建议

如果接入当前 Vue3 + FastAPI 项目，建议新增一组学习接口。

### 9.1 获取当前学习状态

`GET /api/v1/shanghan/progress`

返回：

- 当前进度
- 今日建议模式
- 是否需要课前抽查
- 当前关卡和积分

### 9.2 获取今日任务

`POST /api/v1/shanghan/session/start`

入参：

- 用户状态：清醒 / 一般 / 很散
- 期望模式：轻量版 / 标准版 / 深入版

返回：

- 今日任务卡
- 课前抽查题
- 当前条文第一片段

### 9.3 提交片段回答

`POST /api/v1/shanghan/session/{sessionId}/answer`

入参：

- 片段 ID
- 用户回答
- 操作类型：回答 / 提示 / 答案 / 换个说法 / 跳过 / 停

返回：

- 系统反馈
- 下一步状态
- 是否进入下一片段

### 9.4 完成本条

`POST /api/v1/shanghan/session/{sessionId}/complete-article`

返回：

- 本条总结
- 小测结果
- 掌握度
- 今日得分
- 下一条建议

### 9.5 获取复习列表

`GET /api/v1/shanghan/reviews`

返回：

- 错题
- 薄弱点
- 卡住条文
- 建议复习顺序

## 10. 与现有项目的关系

当前项目主应用是 Vue3 + Element Plus + Pinia / FastAPI。

建议落地方式：

- 前端新增 `ShanghanStudy` 页面和相关路由。
- 后端新增 `shanghan` router。
- 学习状态先用 SQLite 保存，后续再考虑迁移。
- 讲稿原文先从现有 txt/docx 解析生成结构化条文数据。
- `note/伤寒论读书进度.md` 可作为初始数据来源，但网页运行后应由数据库维护进度。

## 11. 验收标准

第一版完成后，按以下标准验收：

1. 打开网页能看到“下一次从第几条开始”。
2. 能选择今天状态，并自动确定学习模式。
3. 能展示今日任务卡。
4. 能按片段学习一条条文。
5. 胡希恕、李冠杰原文阅读必须先让用户归纳，再展示点评。
6. 用户点 `提示` 时按两级提示走，不直接给完整答案。
7. 小测完成后能生成掌握度。
8. 用户点 `停` 后，下次能从停止处继续。
9. 错题能进入复习列表。
10. 已学条文能在目录中显示状态。

### P1

## 13. 设计备注

这个网页最重要的不是“资料多”，而是把学习流程固定住：

```text
任务卡 -> 原文 -> 提问 -> 用户归纳 -> 点评 -> 小测 -> 记录进度
```

只要这个节奏稳定，第一版就有价值。后续再逐步增加题库、卡片、检索和导出。
